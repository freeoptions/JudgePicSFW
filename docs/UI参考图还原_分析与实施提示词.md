## 一、为什么现在看起来仍然不像图一

主要差距在**布局比例、信息密度、表格结构和操作区位置**，配色并不是首要原因。当前代码已经使用白色卡片、浅蓝背景、蓝色主色和小圆角；继续只要求“清爽、现代、精致、接近参考图”，很容易只改几组颜色和边距。

图一原图为 **1672 × 941 像素**；图二原图为 **2556 × 1531 像素**。两图尺寸、任务模式和数据状态不同：图一为内容安全分类且有扫描结果，图二为人物分类且尚无结果。因此不能直接把截图中文字的像素大小当成 WPF 字号，也不能把空列表本身当作布局错误。应统一窗口逻辑尺寸和 DPI，再分别对比空状态及有数据状态。

### 不能只凭截图下结论的地方

- **图二整体灰暗的原因尚未确认。** `App.xaml:5–24` 定义的是浅色配色，`SurfaceBrush` 和 `HeroBrush` 都为白色；`MainWindow.xaml.cs:24` 还显式将窗口背景设为 `SurfaceBrush`。所检查的当前主界面代码没有对应全窗口灰色遮罩。截图工具遮罩、运行版本不同等只是可能性，不能据此断言原因，更不能盲目提高透明度或改成刺眼白色。
- **窗口底部是否被裁切尚未运行验证。** 当前布局的固定列、最小宽度、间距及外边距合计约 1368 DIP，略大于窗口声明的 `MinWidth=1360`；这是可以静态确认的窄窗口风险。图二底部的实际表现还需核对截图范围、最大化边界、DPI 和工作区，不能直接认定为某一项 Windows 设置。
- **图一并不是功能规格的逐项清单。** 它画了阈值滑块、模型下拉选择、分页、速度、剩余时间、GPU 状态等，但当前界面没有相应完整绑定和交互。不能只画控件或写死数值冒充实现。

### 几个容易被“照图改”破坏的语义

1. 当前“来源”数据 `LabelOriginText` 表示样本库、自动判断、人工纠正等**判定来源**，不是图一中的“待扫描”目录。
2. `ConfidenceText` 已包含“置信度”前缀和百分数格式，直接填入置信度列会出现重复文案；应使用数值 `Confidence` 做仅供显示的格式化。
3. 图二处于人物分类。`PrimaryFilterLabel`、`SecondaryFilterLabel`、`CurrentLabelText` 和纠正按钮文案随模式变化，不能全部写死成 SFW / NSFW。
4. 当前 `StopScanCommand` 实际调用取消操作，不具备断点暂停后恢复的完整语义。UI 调整应沿用真实命令，不能凭参考图擅自增加“继续扫描”。
5. 实际软件支持多组源目录、目标目录、样本库、个人模型和确认移动。图一左栏只是更简化的示意，不能为了外观删掉这些能力。

仓库已有的 `docs/superpowers/plans/2026-07-15-ui-workbench-restyle.md` 主要用“收紧间距、改善层级、接近预览”等描述，还缺少栏宽比例、整行高度、五列表格、跨栏按钮位置及同尺度验收标准。本次提示词应补上这些约束。

### 3. 统一文字和控件密度
