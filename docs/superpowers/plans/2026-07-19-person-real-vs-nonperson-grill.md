# 人物/非人物分类 Grill 结论

日期：2026-07-19

## 目标

为 JudgePicSFW 增加一套独立的“真人人物 / 非人物 / 不确定”分类能力，整体流程和现有“内容安全 SFW / NSFW / 不确定”分类相近，但模型、样本、缓存、目标目录、训练记录应与内容安全任务相互独立。

## 分类定义

### 人物

只统计“真人”或“写实真人形象”。

满足以下条件时可判为人物：

- 画面中存在明确可识别的真人。
- AI 生成图如果画面内容是写实真人，也算人物。
- 真人可以在海报、屏幕、相框等画面载体里，只要视觉上是真人且是主要关注点之一。
- 人物不一定必须占满画面，但需要在画面中具有足够主体性。

### 非人物

以下情况归为非人物：

- 二次元人物。
- 3D / CG / 游戏角色。
- 手办、雕像、人台、人体模特。
- 机器人、兽人、怪物、拟人角色。
- 动物、风景、建筑、物品、抽象图、纯文字图。
- 画面中虽有真人，但真人只是非常小的背景点缀，整体更突出背景、场景或物体。
- 只露出过少人体局部，不能明确看出一个真人。
- NSFW 图中只有人体局部时，不因为内容安全原因强制判人物。

### 不确定

以下情况进入不确定：

- 画面太糊、太暗、遮挡严重，无法明确判断是否真人。
- 真人占比较小，但是否属于主体不明显。
- 局部人体元素较多，但无法明确看出是一个真人。
- 写实程度介于真人和 3D / 二次元之间，模型或人工判断拿不准。

## 关键边界

- “是否真人”优先于“是否人形”。人形不等于人物。
- “是否主体”很重要。真人如果只是非常小的背景元素，不算人物。
- 二次元、3D、手办、雕像等不算人物，即使有明显人形。
- 写实 AI 真人图算人物，因为用户关注的是画面内容而不是生成来源。
- 人物/非人物与 SFW/NSFW 互不影响，同一张图可以先被内容安全判为 SFW，再被人物分类判为人物或非人物。

## 用户工作流

用户的日常整理流程预期为：

1. 拿到一批待处理图片。
2. 先用内容安全模式分析，得到 SFW / NSFW / 不确定。
3. 人工纠正内容安全结果。
4. 移动图片到 SFW / NSFW 目录。
5. 将移动后的 SFW 目录作为人物/非人物任务的源目录。
6. 用人物/非人物模式分析 SFW 图片。
7. 人工纠正人物/非人物结果。
8. 移动到用户指定的人物 / 非人物 / 不确定目录。
9. 点击继续训练人物/非人物个人模型。

## 实现方向

人物/非人物任务应仿照内容安全任务，但保持数据隔离。

建议独立维护：

- 人物任务样本库。
- 人物任务目标目录。
- 人物/非人物训练记录。
- 人物/非人物个人模型。
- 人物/非人物固定回放集。
- 人物/非人物 tensor-cache。
- 人物/非人物评测集。

不要复用 SFW/NSFW LoRA 模型来承载人物分类标签。两类任务语义不同，混用会污染训练目标。

## 固定回放集

用户计划后续提供人物与非人物目录，由 Codex 帮忙挑选 1000 张固定回放图片。

建议比例：

- 真人人物：500 张。
- 非人物：500 张。

挑选优先级：

- 真人占比和主体性边界样本。
- 写实 AI 真人样本。
- 背景很突出但包含真人的小比例样本。
- 容易与 3D / 二次元 / 手办混淆的样本。
- 非人物中包含风景、建筑、物品、抽象、二次元、3D、动物等多类别代表样本。
- 尽量去重，避免一批高度相似图占满回放集。

固定回放集与评测集不要重叠，避免评测准确率虚高。

## 缓存策略

人物/非人物任务的 tensor-cache 也设置为约 1GB 上限。

建议：

- 缓存 key 优先使用内容身份，例如 contentId / 内容 hash。
- 路径只作为读取图片的入口，不作为图片身份。
- 超过 1GB 后按最久未使用淘汰。
- 固定回放集缓存可以长期复用。

## 后续待确认

用户暂时还没有确定人物/非人物目标目录。

正式实现前需要用户提供：

- 人物目标目录。
- 非人物目标目录。
- 不确定目标目录是否需要单独配置。
- 人物固定回放源目录。
- 非人物固定回放源目录。
- 人物固定回放目标目录。
- 非人物固定回放目标目录。

## 已确认决策

- 只算真人，不算二次元/3D/手办/雕像/机器人/拟人角色。
- 写实 AI 真人图算人物。
- 真人如果只是很小的背景点缀，整体更突出背景，则不算人物。
- 需要人物 / 非人物 / 不确定三类。
- 需要完整仿照内容安全任务的样本库、目标目录、人工纠正、移动、继续训练能力。
- 人物/非人物模型必须和内容安全模型独立。
- 人物/非人物与内容安全互不影响。
